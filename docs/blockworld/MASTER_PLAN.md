# 宏观规划：昊通机械 · 巨型方块厂区（下一阶段）

> 本文件是给下一个实现者的“需求 + 方案”总表。第 1–3 节是用户要的东西（与引擎无关），第 4 节是**换引擎**（用户最新的指示），第 5–8 节是阶段、验收、风险和待确认问题。
> 原始英文要点版方案：`blockworld/plan/PLAN.md`（基于“保留 ClassiCube”的路线，现在作为 Plan B 保留）。布局图：`park_layout.png`（由 `blockworld/plan/layout.py` 生成）。

## 0. 用户需求原话归纳（按时间顺序，后面的覆盖前面的）

1. 把地图扩大：**巨型工业厂区**，有各种真实的加工中心、数控机床；“一个机械公司应该有的你都得有”；还有园区、宿舍、食堂；**一定要真实、要巨型、要有巨构**。
2. 两档画质：电脑默认超高画质 + 光影，手机默认旧版方块风 → **随后撤回：“那就不用光影了”**。
3. “保留现在的渲染引擎不变，但是添加更多的方块、武器，还有实体生物，这些生物还能在厂区里和机器互动。还有打开背包。”
4. **最新**（在被问到“按 512 格布局开工吗”时）：“那你找一个**性能更好、支持特性更多的现代类 Minecraft 引擎**，**优化一下整体性能**，然后开始干吧！” → 换引擎刚开始调研就被用户叫停，转为本次交接。

所以当前有效需求 = 1 + 3 的内容（巨型厂区 + 方块 + 武器 + 生物/机器互动 + 背包），**不做光影**，引擎**可以换**成更现代、更快、功能更多的方块引擎，同时要做性能优化。

## 1. 不变的约束

- 不出现 “Minecraft” 名称/Logo，不用任何 Mojang 素材或由 Mojang 代码转译的客户端（Eaglercraft 之类因版权与 DMCA 风险排除）。
- 纯静态可托管（Cloudflare Pages / 服务器 nginx），不依赖常驻游戏服务器（服务器只有 1.6 GB 内存且还跑着 QQ bot 等服务）。
- 电脑 + 手机（触屏）都能玩；手机横屏可用。
- 保留：用户两张 GIF 原样动画展示、7 条（以后会更多）动态公告、资料室三本书 → 阅读页、B 站/GitHub/旧版主页/文字版传送门、文字版 `#text`（无 WebGL / SEO 回退）、`/classic/`、`/library.html`、`/read.html`。
- 昊通机械风格（黄黑警示、钢板、荧光橙、HT 标识；品牌为自制，无官方 logo）。
- 先在预览地址出版本（建议服务器 `http://101.132.143.85/v2/` 或单独的 Pages 预览项目），**用户确认后才替换 xueruo.me**。
- 内容要真实，不编造新闻；动态来源是 `content/news/*.md`。

## 3. 功能需求

### 3.1 方块（约 120 种工业材料）
钢板、花纹钢板、混凝土、沥青 + 标线、玻璃幕墙、压型钢板墙面、6 种涂装色的机床外壳、控制面板/屏幕、管道、风管、电缆桥架、格栅、警示条、照明、货架、托盘、木箱等。外加拉丁字母/数字像素字形方块（无限标注 HALL A、CNC-05、1#）。形状：半砖、柱、细栏杆、管道、薄板。

### 3.2 手持工具 / 武器
扳手、锤子、焊枪、（激光）等，能拿在手里挥动；打到人物/生物身上有反应（击退、受击闪烁、粒子/音效）。不做血腥。

### 3.3 实体：NPC 工人、叉车、AGV、行车
- 工人沿路线走动，到机床前停下做“操作”动画（机床可配合有加工动画/火花/指示灯）。
- 叉车、AGV 在仓库和码头循环行驶；桥式行车小车来回移动；龙门吊移动。
- 手机端限制数量（ClassiCube 方案估计 40–80 个，换引擎后重新实测）。
- 路线/行为数据由生成器写进世界数据（例如 `world.json` 的 npc paths），由页面里的“调度器”驱动。

### 3.4 背包
按 B（或手机按钮）打开，**分类标签：材料 / 机械 / 标识 / 工具**，选中直接放进快捷栏。界面中文。

### 3.5 保留的现有交互
点告示牌/书/GIF/传送台（或准星对准按 E、手机点按）弹出中文卡片；传送；文字版；动态从 `content/news` 自动生成。

### 3.6 性能（用户点名“优化整体性能”）
- 目标（建议值，待和用户确认）：中端手机（iPhone 12 级 / 中端安卓）横屏 ≥ 30 fps，桌面集显 ≥ 60 fps；首屏可玩 ≤ 5 s（4G），首包尽量 < 5 MB，其余按区块流式加载。
- 手段：Web Worker 里做网格化、贪心合并（greedy meshing）、视锥/遮挡剔除、按区块流式加载与卸载、LOD/远景简化、实例化渲染重复的机床模型、纹理数组/图集压缩（KTX2/Basis）、手机降视距、实体数量和更新频率分级。

## 4. 换引擎（用户最新方向，尚未开始）

### 4.1 为什么考虑换
ClassiCube 的硬限制：只有一张图集（已用 381/400 格）、自定义 ID 上限 767、世界内不能显示中文（只能做成贴图，极耗图集）、引擎 UI 是英文、单机模式没有 NPC/AI、物理对扩展 ID 有 bug（已关闭物理）、自定义模型需要模拟网络包注入。要做 120 种方块 + 大量标识 + NPC + 背包，在 ClassiCube 上需要一串未验证的引擎补丁（见 `plan/PLAN.md` 第 2、4 节）。

### 4.2 选型标准（按优先级）
1. 浏览器内运行，**电脑 + 手机触屏**都可用（自带或易做虚拟摇杆）。
2. **纯静态托管**，单机即可运行，无需常驻服务端。
3. 许可证允许在个人站上公开分发（MIT/BSD/Apache 最好；LGPL 可以但要留源码/许可说明）；**不含 Mojang 资产**。
4. 实体系统 + 可脚本化 AI（路径跟随、状态机、动画）。
5. 物品 / 背包 / 手持物体系，或容易自己做（HTML UI 叠加也可以）。
6. 大世界：区块流式加载、Worker 网格化、贪心合并、剔除。
7. 自定义方块形状与模型（机床、叉车、行车需要非整格模型）。
8. 脚本化/数据驱动的世界生成（我们是离线生成整张图，需要能导入体素数据）。
9. **原生中文文本**（告示牌、UI），不再靠贴图。
10. 社区活跃、文档、体积。

### 4.4 选型流程（E0，建议 1 天内）
1. 每个入围候选（建议 Luanti-wasm、noa、Voxelize/DVE、自研 three.js 至少 3 个）做同一个 spike：导入当前 256 世界或 512 测试图 → 电脑和手机（真机 + 无头 Chrome 移动模拟）测：首包大小、加载时间、内存、fps、触屏可用性、中文文本、1 个走路的 NPC、1 个自定义模型、背包 UI。
2. 出一张对比表 + 截图发给用户，**由用户拍板**。
3. 定下引擎后，生成器改成“引擎无关”的结构：`zones.py`（区域数据）→ `roads` → `buildings`（外壳）→ `prefabs/*`（参数化机床/车辆/巨构）→ 放置器 → 内容（新闻/书/GIF/传送门）→ 各引擎的导出器（`.cw` 或新格式）。这样即使换引擎失败也能退回 ClassiCube。

- [ ] 512×96×512（或用户认可的尺寸）厂区，17 个区域与布局图一致，4 个巨构可进入/可攀爬观看。

- [ ] ≥ 100 种工业方块，背包按 材料/机械/标识/工具 分类，中文界面。
- [ ] 手持工具能挥动并命中实体产生反馈。
- [ ] 工人会走到机床前做操作动作；叉车/AGV/行车在动；手机上数量受控。
- [ ] 两张 GIF 原样动画 + 点开原图；7 条公告（来自 content/news）可点开；三本书 → 阅读页；4 个传送门可用；文字版可用；`/classic/` 等旧地址可用。
- [ ] 不含 Mojang 素材、页面无 Minecraft 字样/Logo；第三方许可证在页脚或 LICENSES 里注明。
- [ ] 性能达到 3.6 节目标（或给出实测数据并得到用户认可）。
- [ ] 先发预览，用户确认后上线；有一键回滚路径。
- [ ] 动态更新流程写清楚（最好自动化：改 md → 构建 → 部署；自动化部署需用户同意并提供凭据）。

## 7. 风险

- iOS Safari 内存：512 世界在 ClassiCube 上约 100 MB 可行；新引擎需重新实测，NPC 数和视距必须对手机设上限。
- 新引擎在手机触屏、中文字体、静态托管上的可行性未验证（尤其 Voxelize 依赖服务端、Luanti-wasm 体积与性能）。
- 若留在 ClassiCube：扩图集（1024 格）/扩 ID（1024）补丁未测试；单机注入 CustomModel 涉及协议内部；回退方案是告示牌瘦身 + 人形 NPC + 方块模型。
- 1 格 = 1 米时设备再细也有方块感；需要自定义模型/子方块形状来提升真实感。
- 服务器只有 1.6 GB 内存，跑着 QQ bot 等；只放静态文件，不要部署需要常驻进程的游戏服务端。
- 版权：不要引入来源不明的材质包/模型；Luanti 生态素材许可证各异（常见 CC BY-SA），引入前逐个确认。
